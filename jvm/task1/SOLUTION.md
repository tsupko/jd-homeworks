# Решение: Понимание JVM

## Полный разбор каждой строки кода

### Строка 1: `int i = 1;`

**Что происходит в JVM:**

1. **Метаспейс (Metaspace):** Класс `JvmComprehension` уже загружен ClassLoader'ом (или загружается в момент обращения к нему). Метаданные класса (константная таблица, информация о полях, методах) находятся в Metaspace.

2. **Стек (Stack):** Создаётся новый **фрейм метода** (`mainFrame`) для метода `main`. Фрейм содержит:
   - **Локальные переменные (Local Variable Array):** В ячейку `index 1` записывается примитив `int` со значением `1`. Примитивы хранятся **в стеке**, а не в куче.
   - **Operand Stack:** Временные вычисления.

3. **ClassLoader:** Bootstrap ClassLoader загрузил класс `JvmComprehension`. Extension/Application ClassLoader участвовали в загрузке.

---

### Строка 2: `Object o = new Object();`

**Что происходит в JVM:**

1. **Operand Stack:** Выполняется байткод `new java/lang/Object`:
   - Выделяется память под объект `Object` в **Heap (Куча)**.
   - Объект инициализируется: поля устанавливаются в значения по умолчанию (0, null, false), вызывается конструктор `<init>`.
   - Ссылка на объект помещается в operand stack.

2. **Local Variables:** Ссылка (8-битная на 32-битной JVM или 64-битная с compressed refs) записывается в ячейку локальной переменной `index 2` в **стеке** фрейма `mainFrame`.

3. **Heap:** Теперь в куче живёт объект `Object`. Он будет собран GC, когда на него не останется ссылок (после завершения метода).

---

### Строка 3: `Integer ii = 2;`

**Что происходит в JVM:**

1. **Автоупаковка (Autoboxing):** Компилятор преобразует это в эквивалент:
   ```java
   Integer ii = Integer.valueOf(2);
   ```

2. **Integer Cache:** `Integer.valueOf()` проверяет, находится ли значение в диапазоне `[-128, 127]`. Если да — возвращается кэшированный экземпляр из внутреннего пула `Integer.cache[]`, который хранится в **Heap**.

3. **Heap:** Ссылка указывает на кэшированный объект `Integer` со значением `2`. **Новый объект не создаётся** (в отличие от `new Integer(2)`).

4. **Local Variables:** Ссылка записывается в ячейку `index 3` в **стеке**.

---

### Строка 4: `printAll(o, i, ii);`

**Что происходит в JVM:**

1. **Operand Stack — подготовка аргументов:**
   - Ссылка `o` (из локальной переменной) помещается в operand stack.
   - Примитив `i` (значение `1`) копируется в operand stack.
   - Ссылка `ii` (из локальной переменной) помещается в operand stack.

2. **Вызов метода `invokestatic`:** Выполняется байткод `invokestatic #printAll`.

3. **Создание нового фрейма:** Создаётся `printAllFrame` для метода `printAll`. Этот фрейм:
   - Получает аргументы: `o` → параметр `p0`, `i` → параметр `p1`, `ii` → параметр `p2`.
   - Имеет свой собственный Local Variable Array и Operand Stack.

4. **Старый фрейм (`mainFrame`):** Помещается на **стек вызовов (call stack)** как «заблокированный» (paused). Он будет восстановлен после возврата из `printAll`.

---

### Строка 5: `Integer uselessVar = 700;`

**Что происходит в JVM (внутри `printAllFrame`):**

1. **Автоупаковка:** `Integer.valueOf(700)`.

2. **Integer Cache:** Значение `700` **выходит** за пределы кэша `[-128, 127]`. Поэтому создаётся **новый объект** `Integer` в **Heap**.

3. **Heap:** Новый объект `Integer(700)` живёт в куче. На него ссылается только локальная переменная в `printAllFrame`.

4. **Local Variables:** Ссылка записывается в локальную переменную фрейма `printAllFrame`.

5. **GC-потенциал:** После возврата из `printAll` этот объект станет **недостигнутым (unreachable)** и будет собран GC при следующей пробе.

---

### Строка 6: `System.out.println(o.toString() + i + ii);`

**Что происходит в JVM:**

1. **Развёртывание компилятором:**
   ```java
   new StringBuilder().append(o.toString()).append(i).append(ii).toString()
   ```

2. **Детальный разбор:**
   - `o.toString()`: Виртуальный вызов `invokevirtual` → вызывается `Object.toString()`. Результат (String) кладётся в operand stack.
   - `new StringBuilder()`: Выделение нового объекта `StringBuilder` в **Heap**.
   - `StringBuilder.<init>()`: Инициализация StringBuilder.
   - `.append(...)`: Вызов `StringBuilder.append(Object)` → внутри вызывает `String.valueOf()`, который для `ii` (Integer) вызовет `ii.toString()`.
   - `i` (int): Примитив преобразуется в строку через `Integer.toString(i)`.
   - `ii` (Integer): Автовызывание `ii.toString()` через `invokevirtual`.
   - `StringBuilder.toString()`: Создаётся новый объект `String` в **Heap** с итоговым результатом конкатенации.

3. **System.out.println:** Вызов `invokevirtual PrintStream.println(String)` → вывод в консоль.

4. **Память:** В процессе создаются временные объекты:
   - `StringBuilder` (Heap)
   - Несколько промежуточных `String` объектов (Heap)
   - Все они станут недостижимыми после завершения строки и будут собраны GC.

---

### Строка 7: `System.out.println("finished");`

**Что происходит в JVM:**

1. **Возврат из `printAll`:** Фрейм `printAllFrame` **удаляется** со стека вызовов.
   - Все локальные переменные `printAllFrame` становятся недостижимыми.
   - Объект `Integer(700)` → **unreachable** → готов для GC.

2. **Возврат в `mainFrame`:** Фрейм `mainFrame` разблокируется и продолжает выполнение.

3. **Строковый литерал `"finished"`:**
   - Строковые литералы хранятся в **String Pool** (часть Heap, или Metaspace в старых JVM).
   - Если такой литерал уже есть — возвращается ссылка на существующий. Если нет — создаётся новый.

4. **Вызов `println`:** Вывод строки в консоль через `PrintStream`.

5. **Завершение `main`:** Метод `main` завершается → фрейм `mainFrame` удаляется → все локальные переменные `main` (ссылки `o`, `ii`) становятся недостижимыми.

6. **Shutdown JVM:**
   - Запускается финальная сборка мусора.
   - Все недостижимые объекты в Heap собираются.
   - JVM завершает работу.

---

## Сводная таблица по областям памяти

| Область          | Что хранится                                                                 |
|------------------|-------------------------------------------------------------------------------|
| **Metaspace**    | Метаданные класса `JvmComprehension`, байткод методов, константная таблица    |
| **Heap**         | Объекты `Object`, `Integer(2)` (из кэша), `Integer(700)`, `StringBuilder`, `String` объекты, String Pool |
| **Stack**        | Фреймы `mainFrame` и `printAllFrame`, локальные переменные, operand stack     |
| **Integer Cache**| Внутренний массив `Integer.cache[]` в Heap для значений [-128, 127]           |

## Цикл жизни объектов и GC

1. **`Object()`** (строка 2) — живёт до конца `main`, затем собирается GC.
2. **`Integer(2)`** (строка 3) — кэшированный, живёт до shutdown JVM.
3. **`Integer(700)`** (строка 5) — живёт только до возврата из `printAll`, затем собирается GC.
4. **Временные объекты** (StringBuilder, String в строке 6) — собираются GC сразу после завершения строки.

## ClassLoader'ы

- **Bootstrap ClassLoader:** Загрузил базовые классы JDK (`java.lang.Object`, `java.lang.Integer`, `java.lang.String`, `java.lang.System` и т.д.).
- **Extension ClassLoader:** (в старых JDK) Загрузил расширения JDK.
- **Application ClassLoader:** Загрузил класс `JvmComprehension` из classpath.
